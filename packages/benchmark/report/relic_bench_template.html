Relic Load Sweep

Closed-loop saturation, 64 connections, the mean of SATRUNS runs with the spread of those runs as a tapered bar end. Every target ran on its own in the night of 2026-10-30, with the machine left to go quiet between targets, oha on 4 threads on the same 8-core Mac as the server. hyper runs 1, 2 or 4 tokio workers, dusty 1, 2 or 4 executors, the Dart servers 1, 2 or 4 isolates, so a four-way server plus oha stays within the 8 cores. Bars are requests per second; hover a bar for the exact figures, the deviation and the cores each route kept busy.

Machine and method

What every number on this page was measured on and how.

  • Machine. MacBook Pro 16-inch 2019 (MacBookPro16,1), Intel Core i9-9980HK at 2.4 GHz, 8 physical cores, 16 logical, 32 GB, macOS 26.7.1. Server and load tool run on this one machine over loopback.
  • Load tool. oha 1.16.0 with 64 connections kept open, HTTP/1.1 keep-alive, on 4 worker threads. Saturation is closed loop (each connection sends the next request as soon as the response arrives) for 5 seconds, taken as the mean of SATRUNS runs. Then one open-loop run at each of LOADLIST percent of that rate gives the latency columns and the delivered rates; the bars show the saturation rate.
  • Isolation. One target per run of the sweep. Before each target the script waits for the one-minute load average to drop under 1.5, and pauses 60 seconds after it. The sweep ran SWEEPDATES.
  • Cores. CPU time of the server process (user plus system, from the kernel's per-process counters) over the run divided by its wall time. A one-way server plus oha stays under 5 of the 8 cores, a four-way server under 8, though at the ceiling the kernel work on oha's side leaves a four-way server at 2.5 to 3 cores. dart:io servers show more than 1 because of their separate event-handler thread.
  • Threads. hyper runs 1, 2 or 4 tokio workers (a current-thread runtime for 1), dusty 1, 2 or 4 zio executors, the Dart servers 1, 2 or 4 isolates each with its own listener on a shared port.
  • Routes. /plaintext answers 13 bytes with no request headers read. /headers reads User-Agent, Accept-Language and a cookie from a browser-like request and answers their lengths. /browser reads Host, a cookie and If-None-Match and answers 1 KB of JSON with ETag and Cache-Control, or 304 when the validator matches. oha sends an If-None-Match that never matches, so every request builds the full page.
  • TLS. TLS 1.3 with the relic_native test certificate (ECDSA P-256). The 64 connections stay open, so the HTTPS rows cost per record, not per handshake. hyper uses rustls, dusty tls.zig, deno its built-in, the Dart servers SecureSocket (dart:io) or tls.zig (relic_native).
  • Software. Dart 3.13.7, Relic 2.0.0-rc.2 at main 0d1f5260 with the chore-benchmark-sweep branch; AOT rows are dart build cli bundles of the same servers. hyper 1.12.0 on tokio 1.53.2 with rustls 0.23.45, rustc 1.99.1. dusty on Zig 0.17.0 and the same zio commit relic_native pins. Deno 2.9.6. shelf on dart:io HttpServer.
  • Ceiling. Above about 140k requests per second the machine, not the server, sets the rate: oha on 4 threads is itself CPU-bound at 3.7 cores there, and the kernel spends about 45 us per request across both ends of each connection, so the 8 physical cores are used up with the server at 2.5 to 3 cores. Plaintext on two or more threads lands anywhere between 140k and 190k with no stable order (a server over TLS can come out above the same server without, two threads above four), and the open-loop run at that rate falls 10 to 30 percent short of it. Doubling oha's threads or the connections changes none of this. Compare servers on the one-way rows and on the header routes; the multi-way plaintext bars show the ceiling.
  • Open loop check. After the closed-loop saturation, oha offers that same rate in open loop; a notch on every bar marks what it delivered, the table's last column and the hover give the figure.NINETY The notch is never above the mean, since oha offers exactly that rate. A shortfall over 10 percent also prints the figure beside the bar: offering exactly the capacity leaves no slack for the load tool's own timing, which costs most where latency is lowest, on the two-way and four-way rows at the machine's ceiling. SAFER
  • Spread. Every bar is the mean of SATRUNS closed-loop runs, and its end tapers from one standard deviation below the mean to one above, so a crisp end is a repeatable figure and a soft one is not. The hover and the table give the deviation. Differences between two bars inside their tapers are noise.
